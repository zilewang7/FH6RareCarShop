# 逆向与实现思路

本文描述 FH6 “意大利奇珍”库存控制器的研究方法、运行时结构和安全约束。仓库不包含
游戏二进制、反编译文件、内存转储、存档或用户日志。

“意大利奇珍”活动已于 2026-07-23 22:30（UTC+8）结束，本项目开源时活动已经下线。
本文及源码不仅作为技术归档保留，也可作为类似限时活动工具的参考与开发基座。可复用
的重点是结构不变量定位、版本兼容回退、受校验的游戏函数调用和事务失败策略，而不是
某一组固定地址。

## 1. 从可观察行为建立假设

活动每次进入时展示三个展位，每个展位来自固定的 14 辆车，总计 42 辆。完全退出游戏
再进入会改变展示组合，而存档文件没有出现与展位选择一一对应的稳定变化。由此先建立
两个可验证假设：

1. 当前展示车辆主要保存在进程内的活动状态，而不是持久化为一份固定库存。
2. 每个展位拥有自己的候选池、当前库存 ID、车型 ID 和刷新状态。

研究过程只比较“进入场地前、进入后、刷新后、购买后”的运行时状态。进程退出后所有
临时修改都会消失，这也成为后续安全设计的边界。

## 2. 识别车辆目录和展位池

先从多次刷新结果收集车辆原名、年份和展位位置，再把可见组合与内存中的小整数数组
进行交叉验证。最终得到三个互不重叠的 14 元素库存 ID 池，以及每个库存 ID 对应的
车型 ID。

候选展位管理器必须同时满足以下条件：

- 两个对象 vtable 都指向游戏主模块。
- `currentId` 属于该展位的 14 车池。
- `pendingId` 为 `-1` 或同一车池中的合法 ID。
- 池的 `start/end/capacity` 指针有序、对齐且长度恰好为 14。
- 池内 14 个 ID 与已验证目录完全一致。
- 当前车型 ID 与目录中的库存 ID 映射一致。

单个数值或单个指针不足以作为写入依据。只有完整不变量同时成立时，候选对象才会被
接受。

## 3. Manager 的快速定位与兼容回退

已验证版本优先使用 vtable RVA 画像。扫描器只读取已提交、可读写、非 Guard 的私有
内存区域，并按区域组从最可能包含活动对象的位置开始。找到每个展位唯一候选后立即
停止，不必每次遍历整个地址空间。

游戏版本未知或 vtable 改变时，扫描器使用结构回退：

1. 搜索完整的 14 元素池数组，而不是搜索单个车辆 ID。
2. 搜索指向这些数组的指针。
3. 根据已知的池字段偏移反推出管理器对象地址。
4. 使用前述全部不变量重新验证对象。

定位结果只按 `PID + 进程启动时间 + 模块基址` 缓存。下一次操作仍会重新读取对象头、
池和当前车辆；游戏重启后缓存自动失效。

## 4. 定位游戏自己的切换函数

观察当前 ID 变化时的调用路径，可以找到负责提交展位车辆的 setter。实现同时保存已
验证 RVA 和带通配字节的函数前导特征：

- 先检查已验证 RVA 处的机器码是否仍匹配。
- 不匹配时，只扫描游戏主模块的可执行页面。
- 特征必须唯一命中；零个或多个命中都会停用写入。

调用时使用一个最小 x64 stub 传入管理器、目标库存 ID，以及游戏原本使用的通知和
依赖状态重建参数。线程返回后不会直接假定成功，而是重新读取 `currentId`、车型 ID
与 `pendingId`，直到状态稳定并再次通过管理器校验。

因此普通切换不是修改一个孤立整数，而是调用游戏自身维护依赖状态的路径。

## 5. 恢复购买资格对象

购买后，车辆可能保留模型但失去购买入口，也可能连模型对应的交互状态一起卸载。
资格状态不在展位管理器本体内，而在与管理器相邻关联的 SaveState 对象中。

解析流程如下：

1. 在目标管理器附近查找对管理器地址的引用。
2. 在引用附近查找具有预期双 vtable 的 SaveState 对象。
3. 校验 SaveState 的 valid、invalid、eligible 虚函数都位于游戏模块。
4. 校验资格对象指针、布尔字段和值域。
5. 校验资格 getter 的机器码语义为读取预期布尔偏移并返回。
6. 只接受距离最近且唯一的关联结果。

恢复时先把资格布尔值置为可用，再实际调用游戏的 eligible 谓词验证结果。只写字节但
谓词仍返回 false 时，事务立即停止。

每次重购只解析目标展位。某个无关展位已经卸载，不应阻断其他展位。如果目标展位自身
也已卸载，工具会先切换到一辆不同的中转车，等待 SaveState 重新出现并完成全部校验。

## 6. 为什么还需要完整刷新

仅恢复资格字节不能保证 UI 重新创建购买入口。完整链路需要让游戏销毁并重建当前展位
交互：

1. 选择与目标车不同的第一辆中转车，避免 setter 因 ID 未变化而直接返回。
2. 临时把该展位候选池替换为一个经过目录验证的中转 ID。
3. 调用游戏自己的强制刷新函数。
4. 刷新函数返回后立即恢复原始 14 车池。
5. 验证游戏实际选中的中转车与稳定状态。
6. 再通过 setter 切回目标车，重新解析 SaveState 并调用最终资格谓词。

临时单车池没有增加活动之外的车辆。从游戏刷新日志的视角，它仍完成了原有随机选择，
只是候选集合在这次调用期间只有一个合法成员，因此表现为正好“随机”到指定车辆。
最终展示结果与反复退出、重进直到随机命中相同，区别只是等待时间。

## 7. 事务与失败策略

重购会记录所有临时状态：原始车辆、原始池边界与内容、修改过的资格字节。正常失败时
按相反顺序回滚。

远程游戏线程有一个特殊边界：如果等待系统调用失败或线程长时间未返回，调用状态无法
确认。此时强制释放 stub、恢复池或再次调用 setter 可能与仍在运行的游戏线程竞争。
安全策略会停止强制回滚，并提示退出游戏清除进程内状态。

这套失败关闭策略还包括：

- 代码特征不唯一时拒绝调用。
- 指针超出用户地址空间或函数超出游戏模块时拒绝继续。
- 车型映射、池长度或布尔值域异常时拒绝写入。
- 刷新返回不适合作为中转的车辆时有限重试，仍异常则回滚。
- 游戏更新导致布局变化时保留普通只读诊断，不猜测新偏移。

## 8. Xbox 与 Steam 兼容

Xbox 应用版和 Steam 版的主模块布局、vtable RVA 与堆分配顺序不同，但高层对象不变量
一致。兼容层把“已验证版本画像”与“结构回退”分开：已知版本快速定位，未知版本只在
完整结构唯一匹配时继续。

支持新版本时应保留以下证据：

- 游戏文件版本与发行渠道。
- 三个管理器各自的唯一候选和完整 14 车池。
- setter、refresh 特征的唯一命中。
- SaveState、资格对象和 getter 的全部校验结果。
- 至少一次便宜车辆的“购买 -> 入口消失 -> 恢复 -> 再购买”实测。

不要把用户存档、完整内存转储或包含个人路径的原始日志提交到仓库。适配结论应转换成
最小的 RVA、签名、不变量和脱敏测试记录。
