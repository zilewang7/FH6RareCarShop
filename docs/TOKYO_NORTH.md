# 东京北改装车（城市生活）适配记录

版本：2.2.1（Xbox 支持始于 2.2.0）。验证日期：2026-11-22。运行时渠道 / 版本：Xbox 3.483.970.0、Steam 6.483.970.0。

## 使用

解压 `win-x64.zip`，以管理员身份运行 `FH6RareCarShop.exe`。本版自带 .NET 运行时，无需另装 SDK。

1. 游戏进入东京城北 Kado mart 旁、汽车修理店（自動車修理）门口的改装车展位，等待车辆与“出售”交互出现。
2. 工具默认选择“东京北改装车（城市生活）”和 1997 Nissan Skyline GT-R V-Spec（R33），可先在诊断页执行“只读扫描”。R33 与 Altezza 在列表中带紫色“难寻”标签，也可搜索“难寻”。
3. 选择同展位目录中的车辆，点击“应用此展位”，回到游戏检查车辆。
4. 只有买过目标车后购买入口消失时才使用“恢复重购”；操作时切回游戏并停留在展位旁。

这是城市生活系列（Series 7）新增的改装车点位。系列嘉年华游戏列表首次时间为 2026-11-05 14:30 UTC 至 2026-12-03 14:30 UTC；程序显示 UTC+8。是否开放以游戏内为准，日期不会绕过车池校验。

## Xbox 3.483.970.0 实机验证（2026-11-22）

运行环境为 Xbox 应用版 `Microsoft.ForteBaseGame_3.483.970.0_x64__8wekyb3d8bbwe`，游戏停留在东京北展位。

- 定位：独立只读普查按结构不变量扫描全部私有可写内存，得到 48 个同类 manager，双 vtable RVA 均为 `0x6697DE0` / `0x6697F30`；其中只有一个车池与本活动一致。加入画像后，生产 `InspectAsync` 以“Xbox 3.483.970.0 已验证 RVA/vtable”命中，整次只读扫描（含函数特征检查）约 2.3 秒。
- setter 特征唯一命中 `0x1543AC0`；refresh 特征唯一命中 `0x1541D40`。
- owner / SaveState 双表 / 资格双表 RVA：`0x68D42D8` / `0x66984F0,0x6698640` / `0x7187858,0x71879C0`。东京北展位所属实体含 56 个组件，只有一个 SaveState 的 `+0x60` 指向同实体内带 `SeeItDriveIt` 标记、getter 为 `0F B6 41 70 C3` 的资格对象。相对布局与 6.461 构建一致，manager 与 SaveState 的 vtable 间距由 `0x6F0` 变为 `0x710`。
- 独立只读探针在全部 48 个 manager 上运行生产同实体解析器，48/48 唯一解析且所属实体互不相同。
- 生产 `DiagnosePurchaseAsync`：valid=True、invalid=False、eligible=True、资格字节 1。
- 生产 `ApplyAsync`：2023 Civic Type R 切换为 R33，再切换为 Altezza，均约 2 秒内完成；截图确认展位车辆与“出售”入口随之变化。
- 生产 `RestorePurchaseAsync`（未购买的 Altezza）：中转 1997 Civic Type R → 完整刷新 → 切回 Altezza，1.9 秒完成，最终资格判定通过。
- 刷新行为变化：本构建的完整刷新不再按临时单车池选车，连续调用都固定选中 R33（245）。2.1.0 的事务要求刷新结果不同于第一中转车和目标车，因此对 R33 恢复重购会连续 4 次失败（事务未产生需回滚的写入，展位保持 R33）。2.2.0 在刷新结果等于目标车或第一中转车时，用 setter 再切到计划中的第二辆同池中转车，保证最后一步仍是“从另一辆车切回目标车”。修复后对未购买的 R33 实测：中转 1997 Civic Type R → 完整刷新（选中 R33）→ setter 切到 S2000 → 切回 R33，2.2 秒完成，最终资格判定通过，截图确认 R33 与“出售”入口。

## Steam 6.483.970.0 实机验证（2026-11-22）

运行环境为 Steam 版 `forzahorizon6.exe`（文件版本 6.483.970.0），游戏停留在东京北展位。

- 定位：同样的结构普查（约 2.5 分钟扫描 14 GB 私有可写内存）得到唯一一组 48 个 manager，双 vtable RVA 为 `0x66AC1A0` / `0x66AC2F0`；其中只有一个车池与本活动一致，成员与顺序和 Xbox 相同。加入画像后，生产 `InspectAsync` 以“Steam 6.483.970.0 已验证 RVA/vtable”命中，整次只读扫描约 2.3 秒。
- setter 特征唯一命中 `0x15BE2C0`；refresh 特征唯一命中 `0x15BC540`（磁盘上的 Steam exe 代码段加密，特征只在运行时内存中扫描）。
- owner / SaveState 双表 / 资格双表 RVA：`0x68E7038` / `0x66AC8B0,0x66ACA00` / `0x719AAA8,0x719AC10`。所属实体同样含 56 个组件，只有一个 SaveState 的 `+0x60` 指向带 `SeeItDriveIt` 标记、getter 为 `0F B6 41 70 C3` 的资格对象；manager 与 SaveState 的 vtable 间距同为 `0x710`。
- 独立只读探针在全部 48 个 manager 上运行生产同实体解析器，48/48 唯一解析且所属实体互不相同。
- 生产 `DiagnosePurchaseAsync`：valid=True、invalid=False、eligible=True、资格字节 1。
- 生产 `ApplyAsync`：1997 Civic Type R 切换为 R33，再切换为 Altezza，各约 2 秒；截图确认展位车辆与“出售”入口随之变化。
- 生产 `RestorePurchaseAsync`（未购买的 R33、Altezza 各一次）：中转 1997 Civic Type R → 完整刷新 → setter 切到 S2000 → 切回目标车，约 2.0 / 2.1 秒完成，最终资格判定通过，截图确认目标车与“出售”入口。
- 刷新行为：Steam 版完整刷新同样不按临时单车池选车，但不是落到 R33，而是停在第一中转车（Civic，返回值 0，当前 ID 不变）。2.2.0 的二次中转对这种情况同样生效。

## 未收录的其它改装车池

资源中还有两组 16 辆的固定白名单改装车池，当前运行时也存在对应展位：

- 以改装 JDM / 欧洲车为主，含 RX-3 Forza Edition（90）、Autozam AZ-1 改装版（63）等；
- 以 Formula Drift 赛车为主，含 F-150 XLT Lariat Forza Edition（222，说明为“通常只能通过抽奖获得”）。

其余改装车展位由黑名单、价格和车辆分组规则动态生成车池，成员会随游戏目录变化。本版没有收录这些车池：它们没有像 Altezza / R33 这样的本系列难寻车辆，与东京北共用多条库存记录（1、3、64、65、67），需要把目录查询改为按活动区分，并且每个点位都要到场实测。

## 自动化检查

- 离线自检：93 条目录记录，1,251 组同池中转计划，7 个回滚边界用例，28 个车池用例（正序、倒序、重复 ID、池外 ID）；固定 Xbox 3.483.970.0 与 Steam 6.483.970.0 的 manager 与同实体关联画像，并校验东京北库存 / 车型映射、价格系数和“难寻”标记（仅 244、245）。
- `tests/FH6RareCarShop.OwnerTests` 对每个 owner 画像（Xbox 3.483.970.0、Steam 6.483.970.0、Steam 6.461.691.0、Xbox 3.461.691.0）运行同一组 36 项集成测试，共 144 项通过；测试仅对测试进程自有模拟内存进行操作，不打开游戏。
- 界面：离屏渲染真实主窗口，默认活动为东京北、列出 15 辆并默认选中 R33，R33 与 Altezza 显示“难寻”标签；连接 Steam 6.483 进程的只读扫描结果正确回填到界面。
- Release 编译启用 warnings-as-errors。

## 验证边界

Xbox 3.483.970.0 与 Steam 6.483.970.0 的定位、资格诊断、切换和完整重购事务已在游戏内实测；两个新构建都尚未做真实购买后的“入口消失 → 恢复 → 再次购买”闭环，也未覆盖全部 15 辆车逐一购买。资格标记与 getter 的检查本身不等于购买闭环完成。结构不一致或关联不唯一时仍会拒绝对应操作。
